# Expert Call Intelligence

An AI-powered application for analysing expert interview transcripts, answering interview-guide questions, extracting exact supporting quotes, identifying cross-expert themes and disagreements, and answering custom questions across multiple transcripts.

## Overview

This project was built for the Hasamex AI Engineer technical case.

The application analyses three expert calls from the European robotic surgery market:

- France - Dr. Jean Martin, Head of Urology
- Germany - Anna Keller, Former Hospital Procurement Director
- UK - Dr. Emily Carter, Consultant Urologist

The application is designed around one key principle: **AI-generated insights should remain traceable to the original transcript evidence.**

## Features

### Interview Guide Analysis

Answers all six questions from the provided interview guide for each expert, including supporting evidence.

### Exact Quote Extraction

Extracts useful verbatim quotes from the transcripts rather than relying only on generated summaries.

### Timestamped Evidence

Each important answer or quote is linked to its original transcript timestamp and speaker.

### Themes & Disagreements

Identifies common themes and differences across the three expert interviews and supports them with transcript evidence.

### Cross-Transcript Q&A

Users can ask natural-language questions across all three transcripts and receive an evidence-grounded answer with supporting quotes.

## Architecture

```text
Transcript Files
       |
       v
Transcript Parser
       |
       v
Structured Transcript Turns
(expert, speaker, timestamp, text, turn_id)
       |
       v
LLM Analysis / Q&A
       |
       v
Evidence Validation
       |
       +---- Exact Quotes
       +---- Speakers
       +---- Timestamps
       |
       v
Streamlit UI
```

The transcripts are parsed into structured turns while preserving source metadata.

For each AI-generated claim, the model is instructed to reference the relevant transcript turn. The application then validates the returned quote against the original transcript before displaying it.

This prevents the application from relying solely on the LLM to provide accurate citations or timestamps.

## Key Design Decisions

### Source-grounded generation

The model is instructed to use only the provided transcript evidence and not introduce unsupported information.

### Deterministic quote validation

The application does not blindly trust an LLM-generated quote.

The model returns a transcript `turn_id` and quote, after which the application verifies that the quote exists in the referenced source turn.

### Source-controlled timestamps

Timestamps and speaker information are taken from the parsed transcript data rather than generated by the LLM.

### Simple architecture

The provided transcripts are short enough to be processed directly without introducing unnecessary infrastructure such as a vector database.

For a small dataset, this keeps the evidence path simple and auditable.

For a larger dataset, the same interface can be extended with retrieval and reranking.

## Setup

Clone the repository:

```bash
git clone https://github.com/amey-21/expert-call-intelligence.git
cd expert-call-intelligence
```

Create and activate a virtual environment:

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file based on `.env.example` and add the required OpenAI API key:

```env
OPENAI_API_KEY=your_api_key_here
```

## Run the Application

Start the Streamlit application:

```bash
streamlit run app.py
```

The application will open in the browser.

## Run Tests

Run the test suite with:

```bash
pytest
```

The tests cover transcript parsing, evidence handling, validation, and mocked analysis/synthesis flows.

## Hallucination & Accuracy Handling

The application uses several safeguards to reduce unsupported AI-generated information:

1. Transcript content is parsed into structured source turns.
2. Each source turn receives a unique identifier.
3. The LLM is instructed to use only the supplied transcript evidence.
4. Generated evidence includes the source `turn_id`.
5. Returned quotes are checked against the original transcript.
6. Speaker names and timestamps are taken from the source data.
7. Unsupported information is not presented as transcript evidence.

This makes the generated analysis auditable and allows users to trace an answer back to the original interview.


## Limitations

The current implementation is designed for the provided case dataset and is not intended to represent a production-scale transcript intelligence platform.

The current approach relies on sending the relevant transcript content directly to the LLM. For substantially larger transcript collections, a retrieval-based architecture would be more appropriate.
